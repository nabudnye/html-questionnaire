# 从问卷到下一步：两个使用案例

以下案例用于说明工作流。示例回答与后续安排是演示材料，不是真实用户记录，也不是模型效果评测。

## 案例一：安排 RAG 学习路线

### 1. 向 Agent 提出请求

> 我想学习 RAG。请用 html-questionnaire 生成一份中文 HTML 问卷，了解我的技术背景、学习目标和时间安排。等我交回答卷后，再帮我制定学习路线。

### 2. 填写问卷

打开 [RAG 演示问卷](https://nabudnye.github.io/html-questionnaire/)，试着填写：

- Python 经验：还没有用过 Python；补充说明“我有 JavaScript 开发经验”。
- 学习目标：做一个能回答自己文档问题的小原型。
- 资料：自己的 Markdown 笔记或纯文本。
- 时间：每周 3–6 小时。
- 环境：文档只能在本地处理，希望只使用免费资源。

点击“预览答卷”，可以看到未选选项已被省略。点击“复制 Markdown 答卷”或下载文件，将内容交回 Agent。

[查看这组回答的实际导出结果](rag-learning-answers.md)。

### 3. 让 Agent 根据答卷继续

> 这是我的问卷答卷。请根据这些回答安排第一周的 RAG 学习任务，说明哪些选择影响了你的安排；缺少的信息请保留为未知。

合理的下一步应体现这些回答：

| 回答 | 对下一步的影响 |
| --- | --- |
| 熟悉 JavaScript，没用过 Python | 只补齐必要的 Python 语法和文件处理，不从通用编程概念重新学起 |
| 想做文档问答原型 | 把第一次可运行的检索实验作为里程碑 |
| 使用 Markdown 笔记 | 先处理纯文本，暂缓 PDF 解析与 OCR |
| 每周 3–6 小时 | 缩小第一周任务，保留一个能验证结果的练习 |
| 本地处理、免费资源 | 先做本地文本切分和检索；硬件未知时，不直接假定能运行大型本地模型 |

模型仍需根据实际环境检查可行性；问卷负责提供背景，不保证具体方案正确。

## 案例二：澄清个人知识库需求

### 1. 向 Agent 提出请求

> 我想做一个个人知识库。请用 html-questionnaire 先生成一份 HTML 问卷，了解我的资料来源、使用方式、隐私约束和维护意愿，再决定第一版范围。

### 2. 填写并返回答卷

打开[个人知识库演示](https://nabudnye.github.io/html-questionnaire/knowledge-base.html)，选择资料来源和主要用途；不确定的地方可以跳过或选择“暂不确定”。导出后交回 Agent：

> 请基于答卷建议第一版范围，列出保留与暂缓的功能，并解释每项建议对应哪条回答。

如果回答是“Markdown 笔记、快速找到内容、本地处理、少维护、先比较现有工具”，下一步应先比较满足这些约束的工具。如果选择的是“愿意写代码、先做原型”，再进入原型方案。

## 使用边界

问卷中的空白不是否定答案，“暂不确定”不应被改写成确定结论。只有补充说明、没有选择选项，也是一份有效回答。答卷没有自动上传或连接 Agent，需要你主动复制或发送。
