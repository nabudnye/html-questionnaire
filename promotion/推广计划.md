# 两周推广与观察计划

名称保持 `html-questionnaire`。先观察演示与场景介绍是否能带来真实使用，再决定是否更名。

## 已准备的材料

- 中文与英文 README，包含安装命令和可复制提示词。
- RAG 中英文问卷、个人知识库中文问卷。
- 20 秒填写与导出动图、双语截图。
- 两个完整使用案例和一份浏览器实际导出的 Markdown 答卷。
- 社区、社交平台和工作流推荐的[发布草稿](发布文案.md)。

## 建议发布节奏

以下是执行建议，不代表已对外发布或已创建定时任务。

| 时间 | 动作 | 观察内容 |
| --- | --- | --- |
| 第 1 天 | 在自己常用的一个开发者社区发布完整 RAG 案例 | 是否有人理解用途、能否完成安装与首次问卷 |
| 第 3–4 天 | 用短文和动图分享同一案例 | 读者是否愿意打开演示，有哪些重复疑问 |
| 第 7 天 | 整理反馈，修正文案中最常见的理解障碍 | GitHub 访问、安装统计和实际反馈变化 |
| 第 8–10 天 | 发布个人知识库案例 | 项目需求场景是否比学习场景更容易引发使用 |
| 第 14 天 | 回看数据与反馈，选择下一轮主推场景 | 优先改进最影响安装或使用的一处问题 |

## 何时考虑改名

如果多人把它误认为面向客户的调查平台，先调整首屏介绍和示例。只有这种误解持续影响理解时，再评估 `agent-intake` 等用途导向名称，并检查旧链接、安装命令与目录记录的迁移成本。
