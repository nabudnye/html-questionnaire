## 开发者社区：完整案例

### 标题

做了一个 Skill：让 Agent 用离线问卷了解你的需求，再开始工作

### 正文

我做了一个叫 `html-questionnaire` 的 Skill，用来在任务开始前收集自己的背景、目标和约束。

比如我想学 RAG，可以让 Agent 先生成一份 HTML 问卷，集中说明 Python 经验、学习目标、每周时间和本地处理要求。填完后复制 Markdown 答卷交回 Agent，再让它据此安排下一步。

页面支持单选、多选、“暂不确定”和补充说明。所有问题都能跳过，初始不预选。导出的答卷只保留实际回答；没有填写的内容保持未知。

生成结果是一个可以离线打开的 HTML 文件，不需要表单账户或服务器。页面不会上传答案，刷新或关闭会清空未导出的内容。界面支持简体中文和英文。

我准备了两份可以直接填写的演示：

- [RAG 学习背景](https://nabudnye.github.io/html-questionnaire/)
- [个人知识库需求](https://nabudnye.github.io/html-questionnaire/knowledge-base.html)

安装：

```sh
npx skills add nabudnye/html-questionnaire
```

安装后可以这样说：

> 我想学习 RAG。请用 html-questionnaire 生成一份中文 HTML 问卷，了解我的技术背景、学习目标和时间安排。等我交回答卷后，再帮我制定学习路线。

[仓库与完整案例](https://github.com/nabudnye/html-questionnaire) · [skills.sh 页面](https://skills.sh/nabudnye/html-questionnaire/html-questionnaire)

目前验证了 Chromium 中的问卷交互与导出，以及 skills CLI 向 Codex、Claude Code 项目目录的安装。不同 Agent 的自动触发效果还需要实际使用反馈。欢迎分享你在哪类任务里需要先把背景说清楚。

## 第二篇案例：个人知识库

### 标题

做个人知识库之前，我先让 Agent 问清楚这五件事

### 正文

资料来源、主要用途、隐私约束、维护意愿和第一步交付，会直接影响个人知识库的方案选择。

我用 `html-questionnaire` 把这些问题整理成离线表单。例如，选择“Markdown 笔记、本地处理、少维护、先比较工具”，就应先比较符合条件的现有工具；选择“愿意写代码、先做原型”，再讨论原型范围。

这是演示性的决策说明，不是模型效果评测。问卷的作用是把影响下一步的信息集中交给 Agent，减少遗漏。
